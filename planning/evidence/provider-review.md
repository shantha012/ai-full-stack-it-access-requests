Model and schema decision record, added 2026-11-15 from the session explanation and inspected implementation:

The configured extraction model is `gpt-4.1-mini-2025-04-14` through the non-streaming Responses API, as defined in [config.py](../../access_requests/config.py). Pinning a dated model makes the requested producing configuration identifiable across runs. Operators can change it with `--model`; model, prompt, schema, request settings and policy are included in the producing-settings fingerprint so a change invalidates reuse. This records the rationale for pinning and configurability. No comparative live evaluation is recorded to establish that this particular model is the most accurate, fastest or cheapest choice for these messages. The default provider remains mock; real extraction requires explicitly selecting `--provider openai` with API_KEY in the environment.

Provider-side schema enforcement is enabled in every [ResponsesProvider.request](../../access_requests/http_provider.py) payload by `text.format.type="json_schema"`, `text.format.name="access_request"`, `text.format.strict=true` and `text.format.schema=settings.schema`. There is no separate schema-enforcement CLI switch. The default settings load [snapshot.schema.json](../../snapshot.schema.json); `--schema-file` changes the schema sent to the provider. This is a request-level setting, rather than relying solely on the extraction prompt to ask for JSON.

Local admission checks remain necessary for mocks and provider responses. The adapter checks provider error, refusal and completion states; [validate_reply](../../access_requests/validation.py) rejects non-completed/refused envelopes, parses output_text, applies Draft202012Validator to the repository's snapshot.schema.json, enforces ASCII YYYY-MM-DD syntax for each non-null date, and checks every supporting quote against the decoded message before routing. An invalid quote is classified as invalid-response; the pipeline returns status error, null extraction and next_action retry-extraction. The local validator currently uses the repository schema even when --schema-file changes the provider request schema, so a custom request schema does not replace the local acceptance contract. Schema conformity establishes structure; exact quote matching establishes verbatim evidence. Neither establishes factual correctness or evidence completeness.

[T03 and T30–T32](../quote-validation-test-run.txt) passed in the targeted offline run, covering the local schema gate and exact-quote acceptance/rejection. These observations use mocks/fake transport and establish serialization and handling only; no new live model call or comparative benchmark was performed for this decision record.
